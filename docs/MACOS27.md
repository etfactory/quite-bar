# macOS 27 호환성

확인 기준: 2026-10-19, macOS 27.0.1 (26A434).

## 구현 경로

macOS 13–26에서는 상태 항목의 폭을 늘려 아이콘을 화면 밖으로 이동하는 경로를 사용합니다. macOS 27에서는 이 경로 대신 다음 방식으로 가시성을 제어합니다.

1. 공개 Accessibility API로 실행 앱의 `AXExtrasMenuBar` 아이콘 프레임을 읽습니다.
2. 사용자가 옮긴 구분선 기준으로 앱을 분류합니다.
3. `MenuBarClientCore`의 `MBAssessmentModeConfiguration` / `MBAssessmentModeAssertion`을 동적으로 찾아 허용 목록을 적용합니다.
4. 세션 핸들을 유지하는 동안 제한을 유지하고, 복원할 때 `invalidate`합니다.

관련 문서: [NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem), [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement), [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice). 외부 코드에 관한 고지는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)를 참고하세요.

macOS 27 경로는 문서화되지 않은 시스템 인터페이스에 의존합니다. 메뉴 막대 관리용으로 공식 지원되는 공개 숨김 API가 아니므로 다른 Assessment Mode 세션과의 동시 사용이나 향후 OS 호환성을 보장하지 않습니다. App Sandbox를 사용하지 않으며 현재 구현은 Mac App Store 제출용으로 설계하지 않았습니다.

## 보호 장치

| 상황 | 처리 |
| --- | --- |
| API 클래스·selector 없음 | 숨김 미적용, 전체 표시 |
| AX 권한 없음 | 위치를 추측하지 않고 권한 안내 |
| 앱이 응용 프로그램 폴더 밖에 있음 | 숨김 미적용 |
| LaunchServices가 다른 복사본을 가리킴 | 화살표 보호를 위해 숨김 미적용 |
| 시스템 앱 또는 AX에서 누락된 앱 | 기본 허용 |
| 다중 아이콘이 여러 구역에 있음 | 더 잘 보이는 구역 우선 |
| 역전된 점선 또는 다른 화면의 점선 | 배치 오류 안내 |
| 읽는 중 구분선 이동 | 드래그 자동 반영은 한 번 재시도, 계속 바뀌면 보류 |
| 수집 도중 마우스·⌘ 입력 재개 | 키와 마우스를 놓을 때까지 다시 대기 |
| 일반 펼치기 중 드래그 | 항상 숨김 번들 목록을 고정하고 나머지만 재분류 |
| 활성화 실패·4초 초과 | 기존 제한도 해제 |
| 복원 뒤 늦게 도착한 활성화 | 늦은 핸들 즉시 해제 |
| 새 앱 실행 | 기존 구역·표시 상태를 유지하며 실행 앱 허용 목록만 갱신 |
| 기존 숨김 앱 재실행 | 기존 구역의 숨김 규칙 유지 |
| 화면 변경·권한 해제·잠자기 | 캐시 폐기 및 전체 복원 |
| 기존 앱 종료 | 숨김·항상 숨김 상태, 세션 및 구역 캐시 유지 |

새로 등장한 미지정 앱은 기본 표시합니다. 실행 앱 허용 목록 교체가 완료되기 전까지 이전 제한을 유지합니다. 교체 실패 시에는 오류 복원 정책을 따릅니다.

시스템 숫자 식별자 0–63과 실행 중인 `com.apple.*` 번들을 허용합니다. 알려진 시스템 항목을 유지하기 위한 범위이며 향후 식별자까지 포괄한다고 단정하지 않습니다. 시계·네트워크·음량·개인정보 지시 표시 등 시스템 기능의 실제 동작은 수동 점검 대상입니다.

## 현재 제약

- 앱 번들 단위로 제어합니다. 한 앱의 개별 아이콘마다 다른 숨김을 적용하지 못합니다.
- 완전히 숨긴 앱의 AX 위치는 신뢰하지 않습니다. 일반 펼치기 중 드래그는 기존 항상 숨김 목록을 유지하고 보이는 일반 구역만 갱신합니다. 항상 숨김을 다시 지정하려면 설정이나 전체 복원으로 모든 제한을 해제한 상태에서 배치합니다.
- 하나의 화면에서 측정한 앱별 분류가 시스템 전체에 적용됩니다. 화면마다 다른 규칙은 없으며 화면 배치 변경 시 다시 적용해야 합니다.
- 노치나 메뉴 공간 부족으로 AX가 제공하지 않는 아이콘은 숨김 대상으로 확정하지 않습니다. 별도 오버플로 행은 없습니다.
- ‘펼칠 때 메뉴 막대 전체 사용’은 Quiet Bar를 활성화해 짧은 앱 메뉴로 공간을 확보합니다. 메뉴 영역 자체를 제거하지 않으므로 화면 폭에 따른 한계가 남습니다.
- 기본 접기·일반 펼치기·전체 복원은 macOS 27.0.1에서 확인했습니다. 실제 드래그 자동 반영, 다른 OS와 하드웨어, 전체 시스템 기능을 포괄하는 검증은 아직 완료하지 않았습니다. [검증 범위](TESTING.md)를 참고하세요.

## 향후 OS 대응

업데이트 후 문제가 발생하면 먼저 **모든 아이콘 복원** 또는 앱 종료로 제한을 해제합니다. OS 빌드와 `--diagnose` 결과를 기록하고 다음 순서로 조사합니다.

1. 클래스·selector 존재 여부.
2. AX가 상태 항목과 올바른 좌표를 반환하는지.
3. 제한 활성화·무효화가 정상 완료되는지.
4. 시스템 항목이 유지되는지.
5. 사용자 배치와 다중 디스플레이가 일치하는지.

안정적인 공개 API로 구현할 수 있게 되면 해당 경로로 드라이버를 교체합니다. 다른 앱의 리소스나 시스템 파일을 수정하지 않습니다.
