# Golden Gate 호환성 결정

확인 기준: 2026-10-19, 로컬 macOS 27.0.1 (26A434).

## 기존 방식의 문제

이전 Hidden Bar 계열은 상태 항목의 폭을 크게 만들어 왼쪽 아이콘을 밀어냅니다. Hidden Bar 프로젝트는 macOS 27에서 이 동작이 깨졌다고 보고하며, 1.11.1 직접 배포판에 다른 엔진을 추가했습니다. App Store판은 이 수정 경로를 사용할 수 없다고 명시합니다.

- [Hidden Bar 1.11.1 릴리스](https://github.com/dwarvesf/hidden/releases/tag/v1.11.1)
- [macOS 27 호환성 이슈 #360](https://github.com/dwarvesf/hidden/issues/360)
- [네이티브 엔진 도입 커밋](https://github.com/dwarvesf/hidden/commit/546892a7508dd08dc2782de7e6429963f0d7e78f)

Quiet Bar는 위 프로젝트의 동작 조사와 MIT 라이선스 브리지를 참고하되, 앱 UI·컨트롤러·코어 상태 머신은 별도로 구성했습니다. 고지는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)에 있습니다.

## 선택한 방법

1. 공개 Accessibility API로 실행 앱의 `AXExtrasMenuBar` 아이콘 프레임을 읽습니다.
2. 사용자가 옮긴 구분선 기준으로 앱을 분류합니다.
3. `MenuBarClientCore`의 비공개 `MBAssessmentModeConfiguration` / `MBAssessmentModeAssertion`을 동적으로 찾아 허용 목록을 적용합니다.
4. 세션 핸들을 유지하는 동안 제한이 유지되며, 복원할 때 `invalidate`합니다.

관련 문서: [NSStatusItem](https://developer.apple.com/documentation/appkit/nsstatusitem), [AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement), [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice).

이는 Apple이 메뉴 막대 관리 앱용으로 제공한 공개 숨김 API가 아닙니다. 비공개 Assessment Mode의 메뉴 막대 제한 부분에 의존합니다. 다른 Assessment Mode 앱과의 동시 사용, 미래 OS 업데이트, 전체 시스템 동작에 대한 보장은 없습니다.

## 보호 장치

| 상황 | 처리 |
| --- | --- |
| API 클래스·selector 없음 | 숨김 미적용, 전체 표시 |
| AX 권한 없음 | 위치를 추측하지 않음; 설정 안내 |
| 앱이 응용 프로그램 폴더 밖에 있음 | 숨김 미적용 |
| LaunchServices가 다른 복사본을 가리킴 | 자기 버튼 보호를 위해 미적용 |
| Apple 앱 또는 AX에서 누락된 앱 | 기본 허용 |
| 다중 아이콘이 여러 구역에 있음 | 더 잘 보이는 구역 우선 |
| 역전된 점선 또는 다른 화면의 점선 | 배치 오류 안내 |
| 읽는 중 구분선 이동 | 드래그 자동 반영은 한 번 재시도, 계속 바뀌면 보류 |
| 수집 도중 마우스·⌘ 입력 재개 | 키와 마우스를 놓을 때까지 다시 대기 |
| 일반 펼치기 중 드래그 | 항상 숨김 번들 목록을 고정하고 나머지만 재분류 |
| 활성화 실패·4초 초과 | 기존 제한도 해제 |
| 복원 뒤 늦게 도착한 활성화 | 늦은 핸들 즉시 해제 |
| 앱 실행/종료·화면 변경·잠자기 | 캐시 폐기 및 전체 복원 |

시스템 숫자 식별자 0–63을 허용하고, 실행 중인 Apple 번들도 허용합니다. 알려진 시스템 항목을 유지하기 위한 보수적인 범위이며, 향후 추가되는 식별자까지 포괄한다고 단정하지 않습니다. 알림 센터·시계·Wi-Fi·음량·카메라/마이크 표시 등 실제 시스템 동작은 수동 점검 대상입니다.

## 현재 제약

- 앱 번들 단위 제어입니다. 한 앱의 개별 아이콘마다 다른 숨김을 적용하지 못합니다.
- 완전히 숨긴 앱의 AX 위치는 신뢰하지 않습니다. 일반 펼치기 중 드래그는 기존 항상 숨김 목록을 유지하고 보이는 일반 구역만 갱신합니다. 항상 숨김 목록을 다시 정하려면 설정이나 전체 복원으로 모든 제한을 해제한 상태에서 배치합니다.
- 하나의 화면에서 측정한 앱별 분류가 시스템 전체에 적용됩니다. 화면마다 다른 규칙은 없습니다. 화면 배치 변경 시 다시 편집해야 합니다.
- 노치 뒤나 메뉴 공간 부족으로 AX가 제공하지 않는 아이콘은 숨김 대상으로 확정하지 않습니다. 별도 오버플로 행은 아직 없습니다.
- “펼칠 때 메뉴 막대 전체 사용”은 Quiet Bar를 활성화해 짧은 앱 메뉴로 공간을 확보합니다. 메뉴 영역 자체를 강제로 제거하지 않으므로 노치나 화면 폭에 따른 공간 한계는 남습니다. 설정 창이 열려 있을 때는 추가 앱 전환을 하지 않습니다.
- 0.1.1에서 이 Mac의 권한 재등록, 실제 접기·일반 펼치기·전체 복원 경로를 확인했습니다. 다른 하드웨어·OS와 아래의 모든 시스템 기능을 포괄하는 검증은 아니며, 상세 범위는 [TESTING.md](TESTING.md)를 참고하세요.

## 향후 OS 대응

업데이트 뒤 문제 발생 시 먼저 **모든 아이콘 복원** 또는 앱 종료로 제한을 해제합니다. `--diagnose` 결과와 OS 빌드를 기록하고, 아래 순서로 조사합니다.

1. 클래스·selector 존재 여부.
2. AX가 상태 항목과 올바른 좌표를 반환하는지.
3. 제한 활성화·무효화가 정상 완료되는지.
4. 모든 Apple 시스템 항목이 유지되는지.
5. 사용자 배치와 다중 디스플레이가 일치하는지.

공개 API만으로 구현 가능한 안정적인 경로가 생기면 네이티브 드라이버를 교체하는 것이 우선입니다. 다른 앱의 리소스나 시스템 파일을 수정하는 방식은 사용하지 않습니다.
