# 문제 해결

## 먼저 전체 표시로 복원

화살표 우클릭 → **모든 아이콘 복원**, 또는 ⌥-클릭으로 설정을 여세요. 설정 창을 열면 모든 제한이 해제됩니다. 메뉴가 보이지 않으면 앱을 다시 열어 설정을 표시하거나 시스템의 프로세스 관리 도구에서 Quiet Bar를 종료합니다. 현재 방식은 프로세스가 소유하는 제한이므로 프로세스 종료 시 시스템이 이를 해제하는 동작을 전제로 합니다.

앱을 지우는 것만으로 로그인 항목이 정상 해제되는지 추측하지 마세요. 제거하려면 먼저 설정에서 **로그인 시 실행**을 끄고 앱을 종료한 뒤 앱을 휴지통으로 옮깁니다.

## 접기가 안 됨

### 스위치는 켜져 있는데 앱에서 권한이 없다고 나오는 경우

macOS 27의 해당 설정 이름은 **기기 제어 및 데이터 접근**입니다. 이전 macOS의 손쉬운 사용(Accessibility) 허용 항목에 해당합니다.

설정 스위치가 켜져 있어도 실행 앱의 `AXIsProcessTrusted()`가 `false`를 반환할 수 있습니다. 앱을 다시 실행해도 계속된다면 **Quiet Bar의 기존 등록을 제거한 뒤 현재 복사본에서 다시 권한을 요청하고 허용**합니다.

1. 개인정보 보호 및 보안 → 기기 제어 및 데이터 접근에서 **Quiet Bar만** 선택하고 제거(−)합니다.
2. `/Applications/Quiet Bar.app`을 실행하고 앱 안의 **권한 설정 열기**를 누릅니다.
3. 다시 나타난 Quiet Bar 항목을 켭니다.
4. 앱에서 권한 안내가 사라지는지 확인합니다. 필요하면 앱을 완전히 종료하고 다시 실행합니다.

설정에 있는 다른 앱의 권한을 초기화할 필요는 없습니다. ad-hoc 빌드는 코드 내용이 바뀌면 서명 식별용 해시도 달라집니다. 따라서 재빌드·교체 후에도 같은 증상이라면 현재 복사본의 권한을 다시 확인하세요. 켜진 스위치만으로 실행 앱의 실제 승인 여부를 단정하지 않습니다.

### 구분선 위치를 읽지 못했다고 나오는 경우

상태 항목의 창 프레임으로 구분선 위치를 읽고, 창 중앙이 속한 화면을 선택합니다. 기본 화면보다 높은 외장 화면에서는 AX 좌표가 음수일 수 있습니다.

메뉴 막대 화살표를 **⌥-우클릭 → 진단 정보…** 하면 별도 창에서 실행 경로, GUI 앱이 인식한 권한, 구분선·화면 좌표, 최근 AX 항목과 분류·드래그 상태를 확인할 수 있습니다. 진단 정보는 앱 안에 표시하며 전송하지 않습니다. 아래 `--diagnose`는 메뉴 막대 위치를 수집하지 않으며 호출한 터미널/실행기의 권한 문맥을 따를 수 있으므로, 실행 중인 GUI 앱의 진단을 우선하세요.

1. `/Applications/Quiet Bar.app`에서 실행 중인지 확인합니다. 여러 복사본을 동시에 두지 마세요.
2. macOS 27에서는 **시스템 설정 → 개인정보 보호 및 보안 → 기기 제어 및 데이터 접근**에서 Quiet Bar를 허용합니다. 이전 OS에서는 손쉬운 사용 항목입니다. 앱으로 돌아와 다시 적용합니다.
3. 메뉴 막대를 실제로 표시하고 일반 구분선 왼쪽에 제3자 앱 아이콘을 배치합니다. 시스템 아이콘은 숨김 대상이 아닙니다.
4. 점선 구분선을 사용한다면 일반 구분선보다 왼쪽에 두세요. RTL에서는 반대입니다.
5. 설정 창의 오류와 **⌥-우클릭 → 진단 정보…** 결과를 확인합니다. CLI의 기본 검사는 아래 명령으로 실행할 수 있습니다.

```bash
"/Applications/Quiet Bar.app/Contents/MacOS/Quiet Bar" --diagnose
```

## 내 화살표까지 사라짐

프로세스를 종료해 전체 표시로 복원합니다. 응용 프로그램 폴더의 복사본만 사용하세요. Quiet Bar는 실행 위치와 LaunchServices가 해석한 앱이 다르면 적용을 거절하지만, OS의 앱 식별 방식 자체가 바뀌면 추가 수정이 필요할 수 있습니다.

## 배치와 다른 아이콘이 숨겨짐

설정을 열거나 모든 아이콘 복원으로 제한을 먼저 해제한 뒤 다시 배치합니다. 같은 앱이 여러 아이콘을 가지면 개별 분류가 불가능하므로 더 잘 보이는 구역을 따릅니다. 새 앱 실행 시에는 기존 구역을 유지하고, 미지정 새 앱은 기본 표시합니다. 기존 숨김 대상은 다시 실행해도 같은 구역을 따릅니다. 화면 변경 뒤에는 캐시를 버리고 전체 표시로 돌아갑니다. 메뉴 막대 배치를 변경하는 다른 도구가 실행 중이라면 간섭 여부를 확인합니다.

## 다른 앱을 실행하거나 종료하면 펼쳐짐

0.1.3까지는 앱 실행·종료를 모두 전체 복원 사유로 처리했습니다. 0.1.4에서는 기존 앱 종료 시 복원하지 않으며, 새 앱 실행 시에는 실행 앱 허용 목록만 갱신합니다. 두 경우 모두 기존 숨김·항상 숨김 구역과 접힘 상태를 유지합니다. 미지정 새 앱은 기본 표시하고, 기존 숨김 대상이 다시 실행되면 기존 구역을 따릅니다.

화면 변경, 권한 해제, 잠자기, 제한 적용 오류는 계속 전체 복원 사유입니다. 0.1.4 (5)은 종료 문제만 수정한 빌드이며, 새 앱 실행 수정은 0.1.4 (6)에 포함됩니다. 검증 범위는 [TESTING.md](TESTING.md)를 참고하세요.

## 드래그해도 숨김 대상이 바뀌지 않음

접힌 상태라면 화살표로 먼저 일반 구역을 펼칩니다. 메뉴 막대 안에서 ⌘ 키를 누른 채 실제로 아이콘을 옮긴 후 마우스와 ⌘ 키를 모두 놓으세요. 키를 계속 누르는 동안에는 여러 아이콘을 옮길 수 있도록 기다립니다. 단순 클릭이나 4pt 미만 이동은 드래그로 처리하지 않습니다.

일반 펼치기에서는 기존 항상 숨김 목록을 그대로 유지합니다. 항상 숨김 앱을 다시 배치하려면 설정을 열거나 **모든 아이콘 복원**으로 전체 표시한 뒤 점선 안팎으로 옮깁니다. 같은 앱의 아이콘이 일반 구분선 양쪽에 있으면 더 잘 보이는 쪽이 우선하므로 한 아이콘만 안으로 넣어도 앱 전체가 숨겨지지는 않습니다.

배치가 계속 움직이거나 AX 위치를 읽을 수 없으면 현재 표시 상태를 유지합니다. 움직임이 멈춘 뒤 다시 드래그하거나 화살표로 적용하세요. 시스템 앱은 일반 구분선 안으로 옮겨도 숨김 대상에 포함하지 않습니다.

## 자동 숨김이 실행되지 않음

시간에 따른 자동 숨김은 배치 편집 또는 설정 창이 열린 동안에는 동작하지 않습니다. 드래그로 배치를 적용하거나 화살표로 접은 뒤 펼치고, 설정 창을 닫고 다른 앱을 활성화하세요. 포인터가 메뉴 막대 위에 있거나 마우스를 누르고 있으면 연기합니다. 다른 앱의 드롭다운 전체를 감지하지는 않으므로 메뉴 조작 중 자동 접힘이 불편하면 이 기능을 끄세요.

## 펼쳤을 때 메뉴 공간이 부족함

**펼칠 때 메뉴 막대 전체 사용**을 켜면 설정 창이 닫힌 상태에서 Quiet Bar의 짧은 앱 메뉴를 활성화합니다. 메뉴 영역 자체를 없애는 방식은 아니므로 노치·화면 폭 때문에 아이콘이 계속 가려질 수 있습니다. 접기·복원할 때 Quiet Bar가 계속 전면인 경우에만 직전 앱으로 돌아갑니다. 그 사이 직접 다른 앱으로 전환했다면 해당 앱의 포커스를 유지합니다.

## 단축키가 작동하지 않음

설정의 전역 단축키 버튼에 등록한 키 조합이 표시되는지 확인합니다. ‘단축키 설정’으로 표시된다면 새 조합을 등록하세요. 등록 실패 메시지가 있으면 다른 조합을 지정합니다. 녹화에는 ⌘ / ⌃ / ⌥ 중 하나가 필요하며 Esc로 취소할 수 있습니다. 단축키는 물리 키 코드를 저장하므로 키보드 레이아웃을 바꾸면 표시된 문자가 실제 키와 다를 수 있습니다. 새 레이아웃에서 다시 지정하세요.

## 로그인 시 실행이 보류됨

`SMAppService`가 승인을 요구하면 앱 설정에 안내가 표시됩니다. **시스템 설정 → 일반 → 로그인 항목**에서 상태를 확인합니다. 설치 위치와 서명이 바뀌었을 때는 해당 앱 복사본의 상태를 다시 확인하세요. 기본값은 비활성입니다.

## 서명 또는 컴파일 오류

- `resource fork, Finder information ... not allowed`: Documents 동기화의 파일 메타데이터가 빌드 번들에 붙을 수 있습니다. 제공 스크립트는 임시 디렉터리 빌드 후 생성한 앱의 FinderInfo만 제거하고 서명합니다. 파일 공급자가 `build/` 복사본에 메타데이터를 즉시 재부여하면 임시 경로의 서명된 앱을 `ditto --norsrc --noextattr`로 응용 프로그램 폴더에 복사하고 설치본을 검증하세요.
- SwiftUI 매크로의 `sandbox_apply` 오류: 제한된 자동화 환경용 옵션은 [BUILDING.md](BUILDING.md)에 있습니다.
- 개발자 확인 관련 메시지: 기본 빌드 스크립트는 로컬 ad-hoc 서명을 사용합니다. 다른 컴퓨터에 배포할 때는 Developer ID 서명과 공증을 진행하세요. Gatekeeper나 시스템 보안을 전역 해제할 필요가 없습니다.

## 기록할 진단 정보

문제를 재현한 OS 버전·빌드, 앱 버전·실행 경로, 권한 허용 여부, 화면 수·노치 여부, 해당 앱 번들 식별자, 구분선과 아이콘의 배치, 표시된 오류를 기록합니다. `--diagnose`는 OS 버전, 앱 실행 경로, 인터페이스 제공 여부와 권한 상태를 출력합니다. 진단 결과에는 사용자 이름이 포함된 경로가 나타날 수 있으므로 공유 전에 내용을 확인하세요.
