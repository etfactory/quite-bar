# Quiet Bar

Swift로 작성한 macOS 메뉴 막대 정리 앱입니다. **⌘ 키를 누르고 아이콘과 구분선을 드래그해 숨길 범위를 정합니다.**

현재 버전은 `0.1.4`입니다. macOS 13 이상을 대상으로 하며, macOS 27에서 빌드와 일부 실제 동작을 확인했습니다. 지원 범위와 확인하지 않은 항목은 [테스트 기록](docs/TESTING.md)을 참고하세요.

## 빠른 시작

필요 환경: macOS 13 이상, Swift 6.0 이상을 제공하는 Xcode. 이 프로젝트는 Xcode 27 / Swift 6.4 / macOS 27.0.1에서 빌드했습니다. 외부 패키지 다운로드는 없습니다.

```bash
git clone https://github.com/etfactory/quite-bar.git QuietBar
cd QuietBar
open QuietBar.xcodeproj
```

Xcode에서 `QuietBar` 스킴과 `My Mac`을 선택해 빌드할 수 있습니다. 실제 사용에는 다음 명령으로 만든 앱을 `/Applications`로 옮겨 실행하세요.

```bash
./scripts/build.sh
open build
```

`Quiet Bar.app`을 응용 프로그램 폴더로 옮겨 실행합니다. macOS 27에서는 앱 안의 **권한 설정 열기**로 이동해 **개인정보 보호 및 보안 → 기기 제어 및 데이터 접근 → Quiet Bar**를 허용합니다(이전 OS 명칭: 손쉬운 사용). 스위치가 켜져 있어도 앱의 권한 안내가 사라지지 않으면 Quiet Bar의 기존 항목을 제거한 뒤 앱의 버튼으로 다시 등록·허용합니다. [관련 해결 절차](docs/TROUBLESHOOTING.md)를 참고하세요.

## 사용 방법

```text
← 숨김 쪽                                     표시 쪽 →
 [항상 숨김 앱들]  ┆  [숨김 앱들]  │  ›  [항상 표시 앱들]
                  점선           일반   화살표
```

1. Quiet Bar 설정을 열면 항상 숨김 구역까지 모두 표시합니다.
2. 실제 Mac 메뉴 막대에서 **⌘ 키를 누르고 앱 아이콘이나 구분선을 드래그**합니다. 여러 아이콘을 옮길 때는 ⌘ 키를 계속 누르고 있어도 됩니다.
3. 마우스와 ⌘ 키를 모두 놓으면 배치를 확인합니다. 일반 구분선 `│`의 숨김 쪽으로 옮긴 앱은 숨김 대상에 포함하고, 표시 쪽으로 빼면 제외합니다. 대상이 바뀌면 버튼을 누르지 않아도 접습니다.
4. **항상 숨김 구역 사용**을 켜면 점선 `┆`이 추가됩니다. 점선의 숨김 쪽에 배치한 앱은 일반 펼치기에서도 숨깁니다.
5. 메뉴 막대 화살표로 일반 숨김 구역을 접고 펼칩니다. 일반 펼치기 중 아이콘을 옮기면 기존 항상 숨김 대상은 유지하고 일반 숨김 구역만 갱신합니다.

접기가 성공하면 일반·점선 구분선도 함께 숨깁니다. 화살표는 계속 표시하며, 펼치기·배치 편집·오류 복원 때 두 구분선을 다시 표시합니다. ‘항상 숨김’ 구역의 앱은 일반 펼치기에서도 숨긴 상태를 유지합니다. 오른쪽에서 왼쪽으로 읽는 시스템에서는 숨김 방향이 반대입니다. 점선은 일반 구분선의 숨김 쪽에 있어야 합니다.

화살표 우클릭으로 설정, 모든 아이콘 복원, 종료를 선택합니다. ⌥-클릭도 설정을 엽니다. 창을 닫으면 앱은 메뉴 막대에서 계속 실행됩니다. 앱을 종료하면 숨김이 해제됩니다.

## 기능

| 기능 | 동작 |
| --- | --- |
| 위치 기반 숨김 | ⌘-드래그 후 키와 마우스를 놓으면 위치로 구역을 갱신하고 변경 시 자동 접기 |
| 항상 숨김 | 선택적으로 세 번째 구역 사용 |
| 펼칠 때 메뉴 막대 전체 사용 | Quiet Bar의 짧은 앱 메뉴를 활성화해 펼친 아이콘의 공간 확보 |
| 자동 숨김 | 5 / 10 / 15 / 30 / 60초; 포인터가 메뉴 막대 위에 있거나 마우스를 누르는 동안 연기 |
| 전역 단축키 | 키 조합 녹화 및 켜기/끄기; 초기 후보는 ⇧⌘H, 기본 비활성 |
| 로그인 시 실행 | `SMAppService.mainApp`; 기본 비활성 |
| 설정 유지 | UserDefaults와 NSStatusItem 위치 저장 |
| 복원 | 오류, 디스플레이 변경, 권한 해제, 잠자기 진입, Quiet Bar 정상 종료 시 전체 표시 |
| 새 앱 실행 | 기존 구역과 접힘 상태 유지, 미지정 새 앱은 기본 표시 |
| 다른 앱 종료 | 기존 숨김·항상 숨김 상태와 구역 캐시 유지 |

처음 실행할 때는 자동으로 숨기지 않습니다. 설정 창이 열린 동안에는 시간에 따른 자동 숨김을 멈추지만, 사용자가 ⌘-드래그한 배치는 키를 놓으면 반영합니다. 드래그하지 않고 기존 배치를 적용하려면 화살표를 누릅니다. 항상 숨김 대상을 다시 배치하려면 설정이나 **모든 아이콘 복원**으로 전체 표시한 상태에서 옮깁니다.

설정의 **일반** 탭에는 구역 안내, 로그인 시 실행, 시작할 때 설정 표시, 펼칠 때 메뉴 막대 전체 사용, 항상 숨김, 자동 숨김, 전역 단축키를 둡니다. **정보** 탭에는 앱 이름·아이콘·버전과 [etfactory.dev](https://etfactory.dev), [GitHub etfactory](https://github.com/etfactory), [factory@etfactory.dev](mailto:factory@etfactory.dev) 링크를 표시합니다. 기술 설명과 검증 기록은 이 문서와 `docs/`에서 관리합니다. 메뉴 막대 화살표를 **⌥-우클릭 → 진단 정보…** 하면 별도 창에서 실행 앱의 권한·좌표·드래그 반영 상태를 확인할 수 있습니다.

## macOS 27에서 알아둘 점

- 기존 `NSStatusItem.length` 확장 기법을 macOS 27에서는 사용하지 않습니다. 위치는 Accessibility로 읽고 `MenuBarClientCore` 시스템 인터페이스로 숨김을 적용합니다.
- **App Sandbox를 사용하지 않는 로컬 앱**입니다. 현재 방식은 App Store 배포 대상으로 설계하지 않았습니다.
- 같은 앱이 여러 아이콘을 제공하면 함께 숨기거나 표시합니다. 여러 구역에 걸치면 더 잘 보이는 구역이 우선합니다.
- 시스템 앱과 위치를 확인하지 못한 앱은 숨기지 않습니다. 시계, 제어 센터, 네트워크 등 시스템 항목은 보호 대상입니다.
- 다른 앱이 실행되거나 종료되어도 기존 숨김·항상 숨김 구역과 접힘 상태를 유지합니다. 새로 등장한 앱은 기본 표시하고, 이미 숨김 대상으로 지정한 앱은 다시 실행해도 기존 구역을 따릅니다. 디스플레이 구성이 바뀌면 전체 표시로 복원하므로 배치를 확인한 뒤 다시 적용하세요.
- `/Applications/Quiet Bar.app` 또는 `~/Applications/Quiet Bar.app`에서 실행하며, LaunchServices가 같은 복사본을 가리켜야 숨김을 적용합니다.
- 문서화되지 않은 시스템 인터페이스는 macOS 업데이트에 따라 바뀔 수 있습니다. 제공 여부, 활성화 오류, 지연 응답을 확인하고 실패하면 전체 표시로 복원하도록 구현했습니다. 미래 OS 호환성을 보장하지 않습니다.
- macOS 13–26의 기존 길이 확장 엔진도 포함하지만 해당 OS에서의 실제 동작은 아직 검증하지 않았습니다.

## 테스트와 진단

```bash
./scripts/test.sh
"build/Quiet Bar.app/Contents/MacOS/Quiet Bar" --diagnose
```

GUI 상세 진단은 화살표 **⌥-우클릭 → 진단 정보…** 에서 확인합니다. `--diagnose`는 OS, 앱 경로, 문서화되지 않은 시스템 인터페이스 존재 여부, 권한 허용 여부만 출력합니다. 메뉴 막대 항목이나 숨김 세션을 만들지 않습니다.

0.1.3 검증 기록(2026-10-19): 코어 테스트 **32개 통과**, Release arm64/x86_64 빌드 성공. 설치된 앱의 한국어 설정·정보 화면을 확인했습니다. 실제 ⌘-드래그 자동 반영은 아직 검증하지 않았습니다.

0.1.4 (5) 설치본에서는 다른 앱을 ⌘Q로 종료한 뒤 접힘 상태 유지가 사용자 확인되었습니다. 0.1.4 (6)은 새 앱 실행 시 상태 유지와 실행 목록 갱신을 추가한 수정본입니다. 전체 코어 테스트 43개와 Release 범용 빌드가 통과했으며 설치본의 권한 인식을 확인했습니다. 새 앱 실행 후 접힘 상태 유지도 사용자 확인되었습니다. 실제 동작 확인 범위는 [테스트 문서](docs/TESTING.md)에 별도로 기록합니다. 코어 테스트는 실제 메뉴 막대 이벤트나 문서화되지 않은 시스템 인터페이스 동작을 대신하지 않습니다.

## 프로젝트 구성

```text
QuietBar.xcodeproj/       앱 빌드 및 실행 스킴
Sources/QuietBar/         AppKit 상태 항목, SwiftUI 설정, 권한·단축키·로그인 실행
Sources/QuietBarCore/     순수 위치 분류 및 비동기 숨김 세션
Native/                  문서화되지 않은 시스템 인터페이스를 격리한 작은 Objective-C 브리지
Tests/QuietBarCoreTests/  실제 메뉴 막대를 변경하지 않는 단위 테스트
Resources/               앱 아이콘
scripts/                 빌드·테스트·아이콘 생성
docs/                    설계, 호환성, 운영 문서
Package.swift            코어 라이브러리와 테스트만 포함; 앱은 Xcode 프로젝트로 빌드
```

앱 자체의 네트워크 요청, 분석 수집, 외부 런타임 의존성은 없습니다. 정보 탭의 링크를 누르면 기본 브라우저 또는 메일 앱이 열립니다. 외부 코드에 관한 고지는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)에 있습니다.
